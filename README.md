# POLA WFH Attendance: Google Apps Script + LINE LIFF

```
original/   โค้ดเดิม v1.1 (สำรองไว้)
improved/   Apps Script v1.3: วางทับในโปรเจกต์ Apps Script
docs/       หน้า LIFF สำหรับ GitHub Pages (index.html + config.js)
```

## การทำงาน

```
LINE app ─► LIFF (GitHub Pages: docs/index.html)
              │ liff.getIDToken()
              ▼ POST {idToken, action}   (Content-Type: text/plain)
           Apps Script doPost()  ─► ตรวจ ID token กับ api.line.me/oauth2/v2.1/verify → LINE userId
              ▼
           Google Sheet: Employees.LineUserId (คอลัมน์ F) ↔ Attendance
```

- **ครั้งแรก:** พนักงานกรอกอีเมลบริษัท แล้วระบบส่ง OTP 6 หลักไปที่อีเมลนั้น พอกรอก OTP ถูก ระบบจะบันทึก LINE userId ลงคอลัมน์ F ของพนักงานคนนั้น
- **ครั้งถัดไป:** เปิดจาก LINE แล้วใช้งานได้ทันที
- หน้าเว็บ Google เดิม (`doGet`) ยังใช้ได้เหมือนเดิม

## ขั้นตอนติดตั้ง

### 1. Apps Script
1. เปิดโปรเจกต์ แล้ววางเนื้อหา `improved/Code.gs`, `improved/Index.html` และ `improved/appsscript.json` ทับไฟล์เดิม
2. รัน `setup()` จาก editor หนึ่งครั้ง ระบบจะเพิ่มคอลัมน์ `LineUserId` ในชีต Employees
3. ไปที่ **Project Settings → Script properties** แล้วเพิ่ม:
   | Property | ค่า |
   |---|---|
   | `LINE_CHANNEL_ID` | Channel ID ของ LINE Login channel (จากข้อ 2) |
   | `LINE_MESSAGING_TOKEN` | *(ไม่บังคับ)* Channel access token ของ Messaging API ใช้สำหรับแจ้งเตือน |
4. ไปที่ **Deploy → New deployment → Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
   - คัดลอก URL ที่ลงท้ายด้วย `/exec` ไว้ใช้ใน `config.js`
   - ตอนกด authorize ระบบจะขอสิทธิ์ใหม่ 2 อย่าง คือ *external requests* (ไว้ตรวจ token กับ LINE) และ *send email* (ไว้ส่ง OTP)
   - ถ้ายังต้องการหน้าเว็บ Google เดิม ให้เก็บ deployment เดิมที่ตั้งเป็น "Anyone within domain" ไว้ด้วย

### 2. LINE Developers Console
1. สร้าง Provider ถ้ามี LINE OA อยู่แล้ว ให้ใช้ Provider เดียวกับ OA
2. สร้าง **LINE Login channel**
3. คัดลอก **Channel ID** ไปใส่ใน `LINE_CHANNEL_ID`
4. แท็บ **LIFF → Add**
   - Size: **Full**
   - Endpoint URL: `https://<github-user>.github.io/<repo>/`
   - Scopes: **openid** (จำเป็น)
   - คัดลอก **LIFF ID**
5. เปลี่ยนสถานะ channel จาก **Developing → Published** ถ้ายังเป็น Developing จะมีแค่ admin และ tester ที่ login ได้

### 3. GitHub Pages
1. แก้ `docs/config.js` ใส่ `LIFF_ID` และ `API_URL`
2. push ขึ้น GitHub
3. ไปที่ **Settings → Pages → Source: Deploy from a branch → `main` / `/docs`**
4. ถ้าใช้ GitHub แบบฟรี repo ต้องเป็น public ข้อนี้ไม่มีปัญหา เพราะในโค้ดไม่มี secret: ID ของ Spreadsheet และ token เก็บอยู่ใน Script properties

### 4. ให้พนักงานเข้าใช้
ใส่ลิงก์ `https://liff.line.me/<LIFF_ID>` ใน Rich menu ของ LINE OA หรือส่งลิงก์นี้ให้พนักงานโดยตรง

### 5. (ไม่บังคับ) แจ้งเตือนลืม Clock Out เวลา 19:00
1. สร้าง **Messaging API channel** ใต้ **Provider เดียวกัน** เพราะ LINE userId จะตรงกันเฉพาะ channel ที่อยู่ใต้ provider เดียวกัน
2. ออก Channel access token แล้วใส่ใน `LINE_MESSAGING_TOKEN`
3. รัน `installReminder()` จาก editor หนึ่งครั้ง
4. พนักงานต้องเพิ่ม LINE OA เป็นเพื่อนก่อนจึงจะได้รับข้อความ

## การลงเวลา (v2.0): เข้า = กดเช้าสุด, ออก = กดช้าสุดของวัน
- มี**ปุ่มเดียว**ทำงานแบบเครื่องสแกนนิ้ว ทุกครั้งที่กดคือ 1 "punch" กดกี่ครั้งต่อวันก็ได้
  - **เวลาเข้างาน** = punch แรกสุดของวัน
  - **เวลาออกงาน** = punch ล่าสุดของวัน ถ้ากดอีกครั้งตอนเย็น เวลาออกจะถูกเลื่อนเป็นเวลาล่าสุด
- **ชั่วโมงทำงาน** = ออก − เข้า แล้วหักพักเที่ยง 1 ชม. ถ้าช่วงเวลาเกิน 5 ชม. (ค่าคงที่ `LUNCH_BREAK_MIN` และ `LUNCH_AFTER_HOURS` ใน `Code.gs`)
  - ตัวอย่าง: 08:58–17:58 = 9 ชม. หักพักเหลือ **8 ชม.** ส่วน 08:58–12:00 = 3 ชม. 2 น. ไม่หัก
- **นับวันตามปฏิทิน** 00:00–23:59 (Asia/Bangkok) ถ้ากดหลังเที่ยงคืน จะนับเป็นของวันใหม่
- **กันกดเบิ้ล:** ถ้ากดซ้ำภายใน 60 วินาที ระบบจะปฏิเสธ
- **ยืนยันก่อนบันทึก:** ตั้งแต่ครั้งที่ 2 ต้องแตะ 2 ครั้ง และมีข้อความใต้ปุ่มว่า "กดครั้งล่าสุดของวันจะนับเป็นเวลาออกงาน"
- **สถานะ:**
  - ยังไม่ลงเวลา (0 ครั้ง)
  - เข้างานแล้ว (1 ครั้ง) ชั่วโมงนับแบบ real time
  - ลงเวลาออกแล้ว (2 ครั้งขึ้นไป)
  - ในประวัติ วันที่ผ่านไปแล้วแต่มีแค่ 1 ครั้ง = **ไม่ได้ลงเวลาออก**
- **หน้าจอ:** แสดงรายการ "ลงเวลาวันนี้ (N ครั้ง)" บอกเวลาและที่อยู่ของทุกครั้งที่กด
- **ชีต `Punches`** (สร้างอัตโนมัติตอนกดครั้งแรก หรือตอนรัน `setup()`): 1 แถวต่อการกด 1 ครั้ง เพิ่มต่อท้ายอย่างเดียว ไม่แก้แถวเดิม จึงเป็น audit log ในตัว
  | คอลัมน์ | ตัวอย่าง |
  |---|---|
  | `PunchId` | UUID |
  | `Email`, `FullName`, `Department`, `EmployeeId` | ข้อมูลพนักงาน |
  | `WorkDate` / `PunchTime` | `2026-11-03` / `2026-11-03 08:58:00` |
  | `Location` / `AccuracyM` / `Place` | `13.724600,100.579400` / `18` / ที่อยู่จาก Google Maps |
  | `Source` | `LINE` หรือ `WEB` |
- **ชีต `Attendance` เดิม (v1.x):** ไม่ถูกแก้ไขหรือลบ ระบบอ่านมาใช้ด้วย โดยนับ ClockIn และ ClockOut ของแต่ละแถวเป็น punch ประวัติเก่าจึงยังแสดงครบ
- **การสรุปรายวัน:** HR หาเวลาเข้า/ออกของแต่ละคนจากชีต `Punches` ได้ โดยใช้ MIN/MAX ของ `PunchTime` ต่อ `EmployeeId` + `WorkDate` (เช่น ใช้ Pivot table)

## การแท็กตำแหน่ง (Location): บังคับทุกครั้ง
- **ต้องมีตำแหน่งทุกครั้งที่กดลงเวลา** ถ้าไม่อนุญาต Location Service ปุ่มจะกดไม่ได้ และ server จะปฏิเสธคำขอที่ไม่มีตำแหน่ง (code `LOCATION`) ข้ามจากหน้าเว็บไม่ได้
- หน้าเว็บขอตำแหน่ง GPS จากเครื่อง (`navigator.geolocation`) ครั้งแรก LINE หรือเบราว์เซอร์จะถามขออนุญาต
- ตำแหน่งของแต่ละครั้งบันทึกในชีต `Punches` (คอลัมน์ `Location`, `AccuracyM`, `Place`)
- **ก่อนกดลงเวลา** หน้าจอจะแสดงการ์ด "ตำแหน่งปัจจุบันของคุณ" มีที่อยู่ ความแม่นยำ และแผนที่ (OpenStreetMap) พร้อมปุ่มรีเฟรช
  - ตอนกดลงเวลา ระบบใช้ตำแหน่งเดียวกับที่พนักงานเห็น ถ้าตำแหน่งนั้นได้มาไม่เกิน 2 นาที ถ้าเก่ากว่านั้นจะหาตำแหน่งใหม่
  - ถ้าความแม่นยำแย่กว่า ±200 ม. จะขึ้นคำเตือนให้ขยับไปใกล้หน้าต่าง
  - ถ้ายังไม่ได้ตำแหน่ง ปุ่มจะขึ้นว่า "เปิดตำแหน่งก่อนลงเวลา" และกดไม่ได้ จนกว่าจะอนุญาตแล้วกดรีเฟรช
  - ที่อยู่ถูก cache ไว้ 6 ชม. ตามพิกัดที่ปัดเป็นช่องละประมาณ 11 ม. การดูตัวอย่างและการลงเวลาจึงใช้โควตา Google Maps ครั้งเดียว
  - แผนที่โหลดจาก openstreetmap.org โดยเบราว์เซอร์ของพนักงานเอง จึงส่งพิกัดไปที่ OSM ด้วย
- หลังลงเวลา พนักงานเห็นตำแหน่งของทุกครั้งที่กดในวันนี้ และกดเปิดใน Google Maps ได้
- ข้อจำกัด:
  - ตำแหน่งมาจากเครื่องของพนักงาน แอปปลอม GPS สามารถหลอกได้ ใช้เป็นหลักฐานประกอบได้ แต่ไม่ใช่หลักฐานที่ปลอมไม่ได้
  - หน้าเว็บ Google (`doGet`) ทำงานใน iframe ของ Google ซึ่งอาจถูกบล็อกการเข้าถึงตำแหน่ง ถ้าถูกบล็อกจะลงเวลาผ่านหน้านั้นไม่ได้ ให้ใช้ผ่าน LINE
- **PDPA:** ตำแหน่งเป็นข้อมูลส่วนบุคคล ควรแจ้งพนักงานเป็นลายลักษณ์อักษรว่าเก็บข้อมูลเพื่ออะไรและเก็บนานเท่าไร (หน้าจอมีข้อความแจ้งว่าบันทึกเฉพาะตอนกดลงเวลา) และจำกัดสิทธิ์ดูชีตเฉพาะ HR

## ความปลอดภัย
- ระบบระบุตัวพนักงานจาก **ID token ที่ LINE รับรองแล้วเท่านั้น** และไม่เชื่อ userId หรืออีเมลที่ส่งมาจากหน้าเว็บ ระบบตรวจ `iss`, `aud` (= Channel ID) และ `exp` ทุกครั้ง
- การผูกบัญชีใช้ OTP ที่ส่งไปยังอีเมลบริษัท:
  - รหัสสุ่มด้วย SecureRandom ใช้ได้ 10 นาที ใช้ได้ครั้งเดียว และผูกกับ LINE account ที่ขอรหัส
  - กรอกผิด 5 ครั้งรหัสจะถูกยกเลิก
  - ขอรหัสใหม่ได้ 1 ครั้งต่อนาที ทั้งต่อ LINE account และต่ออีเมล
- ระบบตอบเหมือนกันไม่ว่าอีเมลจะอยู่ในรายชื่อพนักงานหรือไม่ จึงใช้หน้านี้เดารายชื่อพนักงานไม่ได้
- LINE 1 บัญชีผูกกับพนักงานได้ 1 คน ถ้าผูกใหม่ ระบบจะลบ LINE ID เดิมออกจากแถวอื่น
- **พนักงานลาออก:** ตั้ง Active = FALSE แล้วระบบจะปฏิเสธทันที ทั้งทาง LINE และทาง Google
- **พนักงานเปลี่ยนเครื่องหรือเปลี่ยนบัญชี LINE:** ผูกใหม่ด้วย OTP หรือให้ HR ลบค่าในคอลัมน์ F
- **ห้ามแชร์ Spreadsheet ให้พนักงาน:** Apps Script ทำงานด้วยสิทธิ์เจ้าของอยู่แล้ว
- `setup()`, `installReminder()` และ `remindClockOut()` รันได้เฉพาะเจ้าของหรือ trigger ของระบบเท่านั้น

## หน้าตรวจสอบรายวันสำหรับ HR

- HR เปิดแผง **ตรวจสอบการลงเวลา — HR** ในแอปเดิมได้ ทั้ง LINE LIFF และ Google web app
- ค่าเริ่มต้นคือวันที่ปัจจุบันตาม Asia/Bangkok เลือกวันที่ย้อนหลัง ปุ่มวันก่อนหน้า/วันถัดไป วันนี้ และรีเฟรชได้ ไม่รับวันที่อนาคต
- แสดงเฉพาะพนักงานที่มีรายการลงเวลาในวันที่เลือก พร้อมรหัส ชื่อ แผนก เวลาเข้าแรกสุด ออกล่าสุด ชั่วโมง สถานะ และรายละเอียดทุก punch รวมลิงก์ตำแหน่งเมื่อมีข้อมูล ไม่ถือว่าผู้ไม่มีรายการลงเวลาเป็นผู้ขาดงาน
- รวม Punches และ Attendance เก่า จัดกลุ่มจากวันที่จริงของ timestamp และรวมรายการเดิมที่ซ้ำกันตรงวินาที ไม่แก้ข้อมูลในชีต ประวัติพนักงาน inactive ยังแสดงได้
- ผู้ดูข้อมูลต้องเป็นพนักงาน Active ที่ยืนยันตัวตนตามเดิม และอีเมลต้องอยู่ใน Script Property **`HR_EMAILS`** เช่น `hr1@company.co.th,hr2@company.co.th` แยกด้วย comma, semicolon หรือขึ้นบรรทัดใหม่ได้
- ถ้าไม่ได้ตั้ง `HR_EMAILS` จะไม่มีใครมีสิทธิ์ HR ตรวจสิทธิ์ทุกครั้งที่ API ฝั่ง server ไม่เชื่อ role/email จากหน้าเว็บ และไม่ส่งรายชื่อ HR ให้ browser

การอัปเดต: วาง `improved/Code.gs` และ `improved/Index.html` ใน Apps Script ตั้ง `HR_EMAILS` ที่ Project Settings → Script properties แล้ว Deploy → Manage deployments → Edit → New version โดยคง deployment URL เดิม หน้า LINE ต้องเผยแพร่ `docs/index.html` เวอร์ชันใหม่ผ่าน GitHub Pages ด้วย ไม่ต้องเพิ่มคอลัมน์ในชีตหรือรัน setup ใหม่สำหรับฟีเจอร์นี้

รันทดสอบสิทธิ์ HR, API ทั้งสองช่องทาง, รายงานย้อนหลัง, เวลาไทย, ข้อมูลเก่า และ syntax ของหน้าเว็บ:

```bash
node --test tests/hr-attendance.test.cjs
```

มี browser smoke test สำหรับการเลือกวัน การแสดงข้อมูลว่าง/ข้อผิดพลาด การป้องกัน response เก่าทับข้อมูลใหม่ และการซ่อนข้อมูลเมื่อสิทธิ์เปลี่ยน ทดสอบทั้ง desktop/mobile ด้วยข้อมูลจำลอง ไม่เชื่อมต่อ API จริง:

```bash
node --test tests/hr-browser.test.cjs
```

บน Windows จะหา Chrome/Edge ที่ติดตั้งไว้ให้ บนระบบอื่นตั้ง `BROWSER_BIN` เป็นพาธ Chrome/Chromium ถ้าไม่พบ browser จะข้าม smoke test นี้

## ทดสอบ
ทดสอบฝั่ง server ด้วย Node โดยจำลอง Apps Script ไว้ ครอบคลุม: ลงเวลาปกติ, กะข้ามเที่ยงคืน, ลืม Clock Out, แถวข้อมูลเก่า, การตรวจตัวตน, การป้องกัน `setup()`, LIFF API (token, OTP, brute force, rate limit) และการแจ้งเตือน
